# UI 코드 검토

PRD.md, README.md와 화면·입력 코드를 읽고 가능한 범위에서 화면 및 관련 테스트를 확인한다. 코드를 직접 수정하지 않는다.

## 점검 체크리스트

- [ ] DOM 구조와 선택자
  - 통과: 보드·점수·종료 안내·Restart 요소를 중복 ID 없이 찾을 수 있다. 실패: 선택자 불일치나 누락·중복 요소로 표시 또는 입력이 깨진다.
- [ ] 상태와 화면의 일치
  - 통과: 렌더링 결과가 보드와 활성 블록 상태를 정확히 반영한다. 실패: 잔상·중복 칸·잘못된 좌표가 표시된다.
- [ ] 렌더링 함수의 부작용
  - 통과: 렌더링이 게임 상태를 변경하거나 타이머·이벤트를 등록하지 않는다. 실패: 그리기 횟수에 따라 게임 동작이 달라진다.
- [ ] 이벤트 수명 관리
  - 통과: 초기화·Restart 후에도 입력당 처리가 한 번이며 종료 시 입력이 차단된다. 실패: 리스너 중복이나 남은 핸들러로 상태가 의도치 않게 바뀐다.
- [ ] 함수와 이름의 가독성
  - 통과: 함수 책임, 좌표 의미, 상태 전이가 이름과 짧은 흐름으로 이해된다. 실패: 여러 책임이 섞이거나 불명확한 이름으로 규칙을 오해할 수 있다.
- [ ] 중복과 상수
  - 통과: 보드 크기·조작키·점수 같은 공통 규칙이 일관되게 관리된다. 실패: 복제된 구현이나 서로 다른 상수가 동작 불일치를 만든다.

## 보고

체크별 판정과 파일·위치 또는 화면 재현 근거를 기록한다. 실행하지 못한 화면·테스트는 미검증으로 표시한다.

문제는 아래 표로 보고한다. 높음은 화면·조작 불가나 상태 훼손, 중간은 일부 표시·이벤트 오류 또는 유지보수 위험, 낮음은 의미가 유지되는 가독성 문제다. 문제가 없으면 없다고 명시한다.
