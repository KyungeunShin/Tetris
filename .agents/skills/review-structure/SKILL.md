# 구조 검토

프로젝트 루트의 PRD.md, README.md와 실제 파일을 비교하고 기존 실행·테스트 명령을 확인한다. 코드를 직접 수정하지 않는다.

## 점검 체크리스트

- [ ] 진입점과 파일 배치
  - 통과: 진입 HTML과 참조 모듈이 존재하고 경로가 일치한다. 실패: 누락된 파일이나 잘못된 경로로 진입이 깨진다.
- [ ] 게임 로직과 UI의 역할 분리
  - 통과: 보드·충돌·점수 로직을 DOM 없이 실행할 수 있다. 실패: 핵심 로직이 DOM이나 화면 상태에 의존한다.
- [ ] 렌더링과 입력의 책임
  - 통과: 렌더링은 상태를 표시하고 입력은 게임 동작을 요청한다. 실패: 렌더링 중 규칙을 변경하거나 입력 처리에 규칙이 중복 구현된다.
- [ ] 모듈 의존성
  - 통과: 모듈의 책임과 호출 방향이 명확하고 초기화가 정상 동작한다. 실패: 순환 의존성이나 중복 상태가 실행·검증을 방해한다.
- [ ] 로컬 실행
  - 통과: README의 명령으로 설치·실행되고 진입 페이지가 정상 로드된다. 실패: 안내된 명령이 실패하거나 필수 설정이 빠져 있다.
- [ ] 테스트 실행 가능성
  - 통과: 문서화된 명령으로 핵심 로직 테스트를 실행할 수 있다. 실패: 테스트 진입점이 없거나 실행이 실패한다.

## 보고

각 체크 항목의 판정과 근거(파일·위치, 실행 명령·결과)를 기록한다. 확인하지 못한 항목은 미검증과 이유를 표시하며 통과로 간주하지 않는다.

발견한 문제는 다음 표로 보고한다. 높음은 실행 불가·핵심 기능 차단, 중간은 테스트나 유지보수를 방해하는 구조, 낮음은 국소적 정리 문제다. 문제가 없으면 없다고 명시한다.
