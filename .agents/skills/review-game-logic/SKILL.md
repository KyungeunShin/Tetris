# 게임 로직 검토

PRD.md와 README.md의 적용 규칙을 먼저 확인한다. 게임 로직과 기존 테스트를 읽고 경계 사례를 재현한다. 코드를 직접 수정하지 않으며 문서에 없는 회전 보정이나 규칙을 필수 요구로 추가하지 않는다.

## 점검 체크리스트

- [ ] 보드 경계 충돌
  - 통과: 좌우 벽·바닥 바로 안쪽은 허용하고 바깥쪽 점유 칸은 거부한다. 실패: 경계에서 한 칸 넘거나 유효한 배치를 거부한다.
- [ ] 고정 블록 충돌
  - 통과: 점유 칸이 겹칠 때만 이동·회전·하강을 거부한다. 실패: 빈 칸을 충돌로 판단하거나 겹침을 허용한다.
- [ ] 생성 위치와 상단 처리
  - 통과: 7종 생성이 정의된 좌표 정책을 따르고 생성 위치가 막히면 종료한다. 실패: 배열 범위를 잘못 참조하거나 생성 충돌을 놓친다.
- [ ] 7종 회전
  - 통과: 회전 후 4칸을 유지하고 4회 회전 시 원형으로 복귀하며 O 형태는 유지된다. 실패: 칸이 사라지거나 잘못된 형태·회전 중심으로 변한다.
- [ ] 실패 동작의 원자성
  - 통과: 거부된 이동·회전이 위치·형태·보드를 그대로 유지한다. 실패: 일부 상태나 원본 형태 데이터가 바뀐다.
- [ ] 하강과 고정
  - 통과: 마지막 유효 위치에 한 번 고정되며 기존 칸을 덮어쓰지 않는다. 실패: 한 칸 어긋남·중복 고정·범위 밖 쓰기가 발생한다.
- [ ] 경계 테스트 근거
  - 통과: 벽 인접 회전, 바닥 회전, 고정 블록 인접, 생성 충돌의 성공·실패 사례가 재현된다. 실패: 해당 사례를 검증할 테스트가 없거나 결과가 규칙과 다르다.

## 보고

판정마다 입력 보드·블록·좌표, 기대값과 실제값, 관련 파일·테스트를 기록한다. 실행하지 못한 검증은 미검증으로 표시한다.

문제는 아래 표로 보고한다. 높음은 보드 훼손·진행 불가·종료 판정 오류, 중간은 특정 형태나 경계의 규칙 오류, 낮음은 기능 오류 없이 부족한 검증 근거다. 문제가 없으면 없다고 명시한다.
